# Session policy is level-triggered: one criterion, evaluated on every input

The extracted session policy (ADR-0001) was edge-triggered: each event ran its own branch, and a resume-on-finish flag patched the window of an enable arriving while a session was still finishing. The module now evaluates one criterion — enabled gate open and latest room info says live — against the session phase on every input: idle and should-record → Start, running and should-not → Stop, finishing → no decision (stop is async). Resume after finishing needs no flag: it falls out of which phase the session ended from — a stopped session (one that went through finishing) resumes iff the world says record at end time, while a naturally ended session is itself the freshest evidence against recording and never resumes on stale live state. This changed one row of the decision matrix: a live event arriving during a natural-stop finish now resumes after the finish completes instead of waiting up to a fallback-poll interval. Every other observable behaviour, including the three preserved quirks, is unchanged.

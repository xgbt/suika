# Recorded segments start at a video keyframe

A segment used to open on whatever tag arrived first — when the stream was caught mid-GOP (every session start, and every reconnect leg), the file began with inter frames that no player can decode until the next keyframe. New segments now wait for the first video keyframe: body tags arriving before it are dropped, while header tags still populate the cache and are injected when the segment opens, so every file starts decodable (ADR-0005 pairs with the pre-existing keyframe-aligned split rules — cuts were already keyframe-aligned, only segment opens were not). Audio-only streams have no video keyframe to wait for and open on the first tag, unchanged. The wait is bounded by the existing health watchdog: a stream that never delivers a keyframe grows no bytes and is aborted after ~30s. Because the dropped pre-keyframe tags now reach the file as injected headers rather than pump writes, injected header tags are counted in the session's written-byte stats (FLV file headers still excluded), including the re-injected headers of every split segment — written bytes are written bytes.

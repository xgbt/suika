# Recording only accepts AVC-coded streams

The recorder's FLV tag-level checks — keyframe detection and sequence-header identification in `internal/data/flv` — are written against the AVC layout (packet types 0/1 after the frame-type nibble). Bilibili also offers HEVC streams, which the stream picker used to accept at a lower priority; legacy-FLV HEVC happened to keep the checks working, but the enhanced-RTMP layout Bilibili is rolling out (FourCC `hvc1` instead of packet types) silently breaks them — keyframe-aligned splitting degrades to forced overrun cuts and header re-injection stops matching. Rather than add codec-aware parsing for a format the recorder does not need, `bestFLVStream` now rejects every non-`avc` codec and `getRoomPlayInfo` only requests `codec=0`; a room offering no AVC stream fails with "no FLV stream candidate", a non-transient error the decision tree records as `last_error` and ends the session on — no retry storm. All four upstream recorders in the workspace record AVC only. Reintroducing HEVC means FourCC-aware parsing in `internal/data/flv` first, tracked as its own effort.
